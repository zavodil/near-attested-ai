# Сценарий демо: Acme Demo

Формулировка для разговора: «EU AI Act controls with proof of enforcement». Не говорить «EU AI Act compliance».

История: в компании работают рекрутер и кредитный аналитик. Compliance задаёт правила, HR-директор и риск-офицер одобряют спорные запросы. Компания доказывает, что происходило с каждым запросом, и не показывает промпты.

## Подготовка

Один раз:

```bash
demo/setup.sh
demo/publish.sh
gh variable set VITE_PROJECT_ID --body "acme-compliance.testnet/compliance-gateway"
gh variable set VITE_SECRETS_ROWS --body "acme-hr-director.testnet/default,acme-risk-officer.testnet/default"
gh variable set VITE_DEMO_MODE --body "0"
```

Перед каждым показом:

1. Открой ссылку `DEMO_LINK` из `demo/accounts.env`: она открывает страницу с ключом рекрутера. Страница аналитика: вставь в настройках `ANALYST_PAYMENT_KEY`.
2. В соседней вкладке открой `app.outlayer.ai/inbox`, переключи сеть на testnet и войди кошельком `acme-hr-director.testnet`. Его ключ лежит в `~/.near-credentials/testnet/`. Войти нужно до первой эскалации: задача шифруется для устройств, которые уже вошли.
3. Прогони весь день заранее, чтобы к показу была готовая выгрузка:

```bash
cd web
npx vite-node ../demo/scenario.ts
npx vite-node ../demo/verify.ts --strict
```

## Показ

### 1. Правила задаёт компания

Нажми «Privileged contract review», затем «Seal and ask». Слева появится блок «Screened under Acme Demo's rules».

Сказать: сотрудник не выбирает правила и не может их обойти. Они лежат в строке секретов проекта компании, а наборы правил читаются из реестра на NEAR и проверяются по хешу.

### 2. Обычный запрос

Покажи ответ и карточку «Signed label».

Сказать: промпт зашифрован в браузере, оператор видит только шифротекст. Label подписан дважды: ключом компании и личным ключом рекрутера. В label нет промпта, только солёный хеш.

### 3. Gate

Покажи блок «Try a gate» со статусом «Accepted». Поставь галочку «every decision model ran in a TEE», статус станет «Refused».

Сказать: так решает система, которая принимает ответ ИИ. Ей нужны только label и закреплённые ключи.

### 4. Запрещённое

Нажми «Should be blocked», затем «Seal and ask». Покажи «Blocked by policy» и сработавшие правила.

Сказать: модель ответа промпт не получила, а отказ тоже подписан.

### 5. Одобрение человеком

Нажми «Needs an officer», затем «Seal and ask». Страница покажет ожидание `acme-hr-director.testnet`.

Перейди во входящие: видны организация, кто спросил, сработавшее правило и промпт. Одобри кошельком и вернись на страницу.

Покажи ответ с заголовком «after the officer's approval» и строку «Approved by» в label.

Сказать: Annex III и надзор человека (Art. 14, Art. 26). Кредитные запросы по той же конфигурации идут риск-офицеру, а не HR.

### 6. Журнал и атаки

Открой `demo/evidence/index.html`. Покажи таблицу подписантов и журнал запросов:

- бывший сотрудник отклонён до запуска;
- сотрудник со своими правилами или своим ключом NEAR AI отклонён;
- отказ офицера: ответа нет;
- личный режим: подпись не сходится с ключом компании;
- поддельный label с чужим именем: обе подписи недействительны.

### 7. Проверка без нас

```bash
npx vite-node ../demo/verify.ts --strict
```

Сказать: команда пересчитывает всё из файлов выгрузки, включая аттестации Intel. Папку можно отдать аудитору. `label.json` идёт gate, остальные файлы сцены идут аудитору.

## Если спросят

- **Скринер в TEE?** Основной скринер Sage работает вне TEE, и label это указывает. Проект `compliance-gateway-tee` скринит моделью в TEE, но её вероятности пока не откалиброваны.
- **Может ли компания подделать?** Владелец проекта может выложить новую версию с теми же ключами. Строгий gate сверяет хеш сборки по аттестации вызова.
- **Сотрудники на аккаунтах NEAR?** Для большой компании это неудобно. Нужен шлюз с SSO, и тогда личность сотрудника будет заявлением шлюза.

## Если что-то зависло

Вызов может остаться в `pending`: на testnet это случалось с личным проектом, причина не установлена. Запрос можно отправить заново. Запасной вариант: показать готовую выгрузку из шага 6.
